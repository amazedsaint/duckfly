# Full-reference stereo capacity and ownership check

Declared before execution. This is an offline Node/WASM capacity diagnostic, not a browser or 25 Hz performance claim. Use the actual packaged 45,669-neuron Flyvis model, verified sparse arrays/checkpoint, signed spatial extraction, and frozen neural-map-flow-v2.js. No changes to those components are authorized by this benchmark.

For 1, 2 and 8 ducks (2, 4 and 16 separately allocated eyes), warm up four group intervals, then retain 64 measured intervals per group size. Each interval represents 40 ms of neural time: 20 consecutive 2 ms WASM updates per eye, followed by signed raw/delta extraction and the v2 pairwise spatial-temporal decoder. Execute eyes sequentially in a shared WASM model, matching its shared immutable weight design. Record elapsed wall time around the entire group, plus sequential component durations. Compute percentiles directly from retained group durations, never by adding per-eye percentiles. Group order is 1, 2, 8 ducks, so order, JIT and concurrent process load are possible confounds.

Retinal inputs are deterministic precomputed 721-value synthetic grating samples in the verified model input coordinate order. Distinct phases and translation angles prevent identical eye histories. Condition each eye for 500 actual model steps using a fade into its first image; report setup costs separately. Calibration uses the previously frozen minimum gradient 0.006455187013519394, with no retuning. Motion accuracy is not evaluated here.

Included in timed group intervals: 20 model updates per eye, model input fill/index mapping, signed 8-population extraction/copies, v2 decoder, and loop bookkeeping. Excluded: loading/decompression/hashing, 500-step conditioning, stimulus generation, image capture, RGBA-to-retina projection, worker transfer, serialization/export, browser UI, and physics. The physical-pilot approximately 63 ms binocular core cost is a separate browser observation and cannot be directly compared without matching these workloads.

Before each group's timing, step one eye and verify all untouched eyes remain bit-identical. Restore the stepped eye and verify peers again. Dispose all eyes after each group; require live allocation counts and live byte counts to return to the model-only baseline. In a separate lifecycle probe, verify duplicate disposal, rejection of operations through a disposed eye handle, unchanged replacement state after rejected stale-handle operations, and allocation reuse over repeated create/dispose cycles. WASM linear memory is a high-water reservation and is not expected to shrink on release; distinguish allocation release from reservation size.

Retain model/source hashes, machine/runtime metadata, per-interval raw timing samples, sampled concurrent process CPU summaries, lifecycle assertions and any failures. No model/body promotion. Do not infer real-time app capacity from this diagnostic.
